# 架构与数据模型

## 组成

```
浏览器 / 桌面窗口  ──fetch──>  Flask app.py (127.0.0.1:8765)
                                ├─ /api/query|add|update|delete ──> storage.py ──> SQLite
                                ├─ /api/version  供页面轮询感知后台写入
                                └─ /api/refresh-nav ──> nav_fetch.py ──> 中银理财官网
launchd:
  com.financeledger.web  开机自启、KeepAlive
  com.financeledger.nav  每天 08:00 抓净值
```

## 数据表

统一物理结构 `record_id + data(JSON) + updated_at`，WAL 模式，写操作加线程锁。

| databaseId | 逻辑表 | 用途 |
| --- | --- | --- |
| `R4EP1k4l2TSnv3MWALkCiN` | assets | 资产台账 |
| `470rjrUP5bjKVeFfzTH0qU` | txn | 交易流水 |
| `Epene6sRljkIPqp7deopV8` | snapshot | 市值快照 |
| `hpr7iAwVjW4B1yUKR4Iym9` | audit | 操作留痕 |
| `L2XpEYpZb71srUm0Jt3fXN` | rate | 汇率设置 |

## 数据契约

- 写入 `properties` 用 `{text/number/date/select: 值}` 包裹格式；`storage.flatten()` 解包成标量后落库。
- 查询返回扁平记录并带 `record_id`，避免页面数字解析成 0。
- 净值跟踪信息打包在 assets「备注」JSON：`{memo, share, nav, navDate, track}`。解析失败按纯文本处理，不改表结构。

## 净值抓取要点

- 接口按日期**升序**返回，必须取 `data[-1]`。
- 销售代码与官网份额代码不同，映射在 `mapping.json`；备注里的 `track` 优先。
- 有份额才重算市值；无代码（存款类）跳过。
- 每次成功更新写一条市值快照 + 一条操作留痕，留痕记录更新前旧净值。
